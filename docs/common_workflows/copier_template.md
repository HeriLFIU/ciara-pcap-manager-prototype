# 🧬 Using and Updating the Copier Template

This project was generated by [Copier](https://copier.readthedocs.io/) from the
template at `https://github.com/HeriLFIU/python-ci-copier-template.git`. Unlike a one-off `git clone`, that
link is *durable*: when the template gains a new hook, a CI fix, or a better
default, you can pull it into this project without re-doing the work by hand.

## Day-to-Day Workflows

### Installing Copier

Copier is a standalone tool, not a project dependency. Install it once, globally:

```bash
uv tool install copier
```

Verify it, and upgrade it later with the same command plus `--upgrade`:

```bash
copier --version
```

### The answers file

`.copier-answers.yml` at the project root is the link between this project and
its template. It records three kinds of thing:

- `_src_path` — where the template lives.
- `_commit` — the exact template version this project was last generated from.
- every answer you gave, by question name.

```yaml
_commit: v1.2.0
_src_path: https://github.com/HeriLFIU/python-ci-copier-template.git
project_name: CIARA PCAP Prototype
package_name: ciara_pcap_manager_prototype
```

> **⚠️ Never edit `.copier-answers.yml` by hand.** Copier treats it as a factual
> record of what produced the files on disk. Hand-editing it makes Copier merge
> against a state that never existed, and the result is unpredictable. Change
> answers by re-running Copier instead — see
> [Changing an answer](#changing-an-answer).

Commit this file. An update run started from a project without it has nothing
to merge against.

### Generating a *new* project from the template

You do not need this project to start another one. Point Copier at the template:

```bash
copier copy https://github.com/HeriLFIU/python-ci-copier-template.git path/to/new-project
```

Copier asks each question, writes the project, and drops in a fresh
`.copier-answers.yml`. Then initialise git immediately — updates require a git
repository with a clean tree:

```bash
cd path/to/new-project
git init -b main
git add -A
git commit -m "chore: initial commit from template"
```

Templates hosted on a forge can be addressed with a shortcut instead of a URL:

```bash
copier copy gh:namespace/template-repo new-project   # GitHub
copier copy gl:namespace/template-repo new-project   # GitLab
```

### Updating this project from the template

This is the command you will use most:

```bash
copier update
```

Two preconditions, both enforced:

1. The working tree must be **clean**. Commit or stash first.
1. `.copier-answers.yml` must be present and committed.

What Copier actually does is a three-way merge:

1. Regenerate the project from the **old** template version and the **old**
   answers — that is the baseline it assumes you started from.
1. Diff that baseline against the project as it exists now. That diff is *your*
   work.
1. Regenerate from the **new** template version and your (possibly updated)
   answers.
1. Re-apply your diff on top.

That is why your own edits survive: they are replayed, not overwritten.

By default Copier updates to the newest **git tag** on the template, sorted by
PEP 440 — not to the newest commit. To track the tip of the default branch
instead:

```bash
copier update --vcs-ref=HEAD
```

### Reviewing before you commit

Copier writes files but never commits. Always look before you leap:

```bash
copier update --pretend      # dry run: report changes, write nothing
copier update                # for real
git status
git diff
```

## Resolving Conflicts

A conflict happens when the template changed the same lines you changed. Copier
does not guess — it hands you both sides.

### Inline markers (the default)

```bash
copier update --conflict inline
```

The file is written with the same markers `git merge` produces. The example
below is indented by two spaces so that this documentation file does not itself
trip the `check-merge-conflict` hook; in a real conflicted file the markers
start at column 0:

```text
  <<<<<<< before updating
      --fail-under=90 \
  =======
      --fail-under=95 \
  >>>>>>> after updating
```

`before updating` is your current content. `after updating` is what the new
template version wants. Anchoring the search to the start of the line finds
every real marker without matching prose that merely mentions them:

```bash
git grep -n "^<<<<<<<"
```

Resolve exactly as you would a merge conflict: edit the file so it contains the
version you actually want, delete all three marker lines, then stage it.

> **⚠️ Conflict markers are valid text, not a build error.** Nothing stops you
> from committing them. The `check-merge-conflict` prek hook is your safety net
> — it fails the commit if any marker survives. Do not bypass it.

### Reject files

```bash
copier update --conflict rej
```

In this mode the file itself is left free of markers: it contains the **new
template version** of the conflicting region, and the hunk that could not be
applied — *your* local change — is written to a `<file>.rej` beside it.

> **⚠️ Read that again: in `rej` mode your local edit is not in the file.** It
> is only in the `.rej`. If you delete the `.rej` without reading it, you have
> silently discarded your own change. `inline` is the safer default precisely
> because it keeps both sides in front of you.

```bash
find . -name "*.rej"
cat pyproject.toml.rej
```

A `.rej` is an ordinary unified diff, with the lines that failed to apply:

```text
  diff a/pyproject.toml b/pyproject.toml (rejected hunks)
  @@ -44,7 +44,7 @@ test = [
  -lint = ["ruff>=0.15.13", "codespell>=2.2.6", "pyright>=1.1.410"]
  +lint = ["ruff>=0.16.0", "codespell>=2.2.6", "pyright>=1.1.410"]
```

Re-apply what you want by hand, then delete the `.rej` files — they are not
meant to be committed.

### Turning down the sensitivity

Copier decides what conflicts using three lines of surrounding context. On files
that were reformatted or heavily rewritten, that can produce conflicts where the
change was actually harmless. Lower it for a more forgiving merge, or raise it
for a stricter one:

```bash
copier update --context-lines 1     # more resilient, may miss-place a hunk
copier update --context-lines 5     # more accurate, more conflicts
```

## Additional Copier Features

### Changing an answer

Answers are not frozen. Re-run the update and override the one you want; every
other answer is reused as-is:

```bash
copier update --defaults --data line_length=100
copier update --defaults --data include_profiling=false
```

To be re-asked everything interactively, drop `--defaults`. To be asked only the
questions you have never answered — the ones added by a newer template version —
use:

```bash
copier update --skip-answered
```

To re-ask one specific question while defaulting the rest:

```bash
copier update --defaults --ask "license_id"
```

### Answering from a file

For reproducible generation — in CI, or across a fleet of repositories — put the
answers in a YAML file instead of typing them:

```yaml
# answers.yml
project_name: Payments API
package_name: payments_api
author_full_name: Ada Lovelace
author_email: ada@example.com
python_version: "3.13"
include_profiling: false
```

```bash
copier copy --data-file answers.yml https://github.com/HeriLFIU/python-ci-copier-template.git payments-api
```

`--data key=value` does the same thing for one-off values and can be repeated.

### `update` versus `recopy`

| Command         | Keeps your edits  | Keeps your answers | Use when                                      |
| --------------- | ----------------- | ------------------ | --------------------------------------------- |
| `copier update` | yes (3-way merge) | yes                | Normal case. Almost always this one.          |
| `copier recopy` | **no**            | yes                | The project drifted so far a merge is useless |

`recopy` re-renders the template over the project as if for the first time,
ignoring everything you changed since. It is a blunt instrument — commit first,
then read `git diff` very carefully.

Files matched by `_skip_if_exists` in the template are protected even from
`recopy`. In this template that covers `src/**`, `tests/**` and `CHANGELOG.md`,
so a recopy will not delete your application code.

### Checking whether an update is available

```bash
copier check-update
```

Reports whether the template has a newer version than `_commit` records, without
changing anything. Useful as a scheduled CI job.

### Skipping and excluding files

To leave specific paths untouched by this run:

```bash
copier update --skip "README.md" --skip "docs/**"
```

To drop paths from the generated output entirely:

```bash
copier copy --exclude "archive/**" https://github.com/HeriLFIU/python-ci-copier-template.git new-project
```

### Trust, tasks, and migrations

Copier templates *can* run commands on your machine, through two features:

- **Tasks** (`_tasks`) run after files are written, on copy and on update.
- **Migrations** (`_migrations`) run only on update, once, when crossing a
  specific template version — the mechanism a template uses to say "when you
  move to v2, this file has to be renamed".

Both are disabled unless you opt in:

```bash
copier update --trust
```

This template deliberately defines **no** tasks, migrations or Jinja extensions,
so it never needs `--trust`. If a future version of it adds one, `--trust`
becomes mandatory and you should read the template's `copier.yml` before
granting it. The same caution applies to any third-party template.

To take an update but skip its tasks:

```bash
copier update --trust --skip-tasks
```

### Useful flags at a glance

| Flag                      | Effect                                                     |
| ------------------------- | ---------------------------------------------------------- |
| `-n`, `--pretend`         | Dry run; report what would change and write nothing        |
| `-l`, `--defaults`        | Do not prompt; use remembered or default answers           |
| `-d`, `--data K=V`        | Override one answer; repeatable                            |
| `--data-file FILE`        | Load all answers from a YAML file                          |
| `-r`, `--vcs-ref REF`     | Use a specific tag, branch or commit of the template       |
| `-o`, `--conflict MODE`   | `inline` (default) or `rej`                                |
| `-c`, `--context-lines N` | Context used for conflict detection; default 3             |
| `-A`, `--skip-answered`   | Do not re-ask questions that already have answers          |
| `-s`, `--skip PATTERN`    | Leave matching existing files alone; repeatable            |
| `-x`, `--exclude PATTERN` | Do not copy matching paths at all; repeatable              |
| `-q`, `--quiet`           | Suppress status output                                     |
| `--trust`                 | Allow the template to run tasks, migrations and extensions |

Full reference: <https://copier.readthedocs.io/en/stable/reference/cli/>

## Troubleshooting

| Symptom                                              | Cause and fix                                                                                              |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `Destination repository is dirty`                    | Uncommitted changes. Commit or `git stash` first — Copier needs a clean baseline to diff against.          |
| `Cannot find the answers file`                       | Run from the project root, or pass `--answers-file path/to/.copier-answers.yml`.                           |
| Update reports "no changes" but the template moved   | Copier follows git **tags** by default. Either tag the template, or run `copier update --vcs-ref=HEAD`.    |
| Conflict markers everywhere after a big refactor     | Retry with `--context-lines 1`, or take the change file by file with `--conflict rej`.                     |
| A question is never asked                            | It has a `when:` condition that evaluated false, or you passed `--defaults`. Force it with `--ask "name"`. |
| Template asks a brand-new question on every update   | Expected — new template versions add questions. `--skip-answered` asks only those.                         |
| You edited `.copier-answers.yml` and updates are odd | Restore it from git history (`git checkout <commit> -- .copier-answers.yml`) and redo the change properly. |
